# Кабинет заказчика и amoCRM

`/lk` — рабочий кабинет: вход по телефону и паролю, этапы, прогресс, фото, видео и переписка. Сейчас по умолчанию включена демонстрация. Телефон `+7 (900) 000-00-00`, пароль `Dom2026!`. Сведения о стройке вымышлены, фотографии взяты из иллюстраций сайта, видео — 9-секундное слайд-шоу этих изображений. Демо не делает запросов в amoCRM; новые сообщения изолированы в сессии и удаляются при выходе.

## Подключение

1. На сервере задать `CABINET_MODE=amocrm`, `AMO_DOMAIN`, `AMO_TOKEN`, `AMO_ADMIN_SECRET`, `CABINET_ORIGIN` (HTTPS-origin без слэша), `CABINET_DATA_DIR` (постоянный приватный каталог), `CABINET_MEDIA_HOSTS` (точные имена хостов фото и видео). Секреты никогда не попадают в `NEXT_PUBLIC_*` или браузер.
2. Перезапустить сервер. В этом режиме демонстрационный пароль не работает; сбой CRM показывает ошибку и не заменяет данные вымышленными.
3. Связать контакт клиента с его сделкой в amoCRM и заполнить телефон контакта. Выполнить служебный запрос создания кабинета из вашей серверной интеграции.
4. Опубликовать первый отчёт в сделке. Передать клиенту выданный пароль по защищённому каналу. Этот проект сам не отправляет SMS или сообщения клиенту.

Интеграция использует официальные [сделки](https://www.amocrm.ru/developers/content/crm_platform/leads-api), [контакты](https://www.amocrm.ru/developers/content/crm_platform/contacts-api) и [примечания amoCRM](https://www.amocrm.ru/developers/content/crm_platform/events-and-notes). Это обмен через примечания сделки, а не подключение к amoCRM Chats API. Внешний вид виджета в самой CRM в эту версию не входит.

## Создание, сброс и закрытие доступа

Все методы `/api/internal/amocrm/cabinet` требуют серверный заголовок `x-admin-secret: <AMO_ADMIN_SECRET>`. Никогда не вызывать их из публичного браузера. Параметры JSON:

```json
{"leadId":123456,"contactId":654321,"phone":"+7 (900) 111-22-33"}
```

`POST` проверяет, что контакт прикреплён к сделке, а телефон действительно записан в контакте. Возвращает `id`, `phone`, случайный `password` и `loginPath`. Пароль возвращается однократно; сохраняется только scrypt-хеш. Повторный запрос без `reset:true` вернёт 409. `reset:true` для той же сделки/контакта выдаёт новый пароль и отзывает старые сессии. Один номер пока соответствует одной стройке; несколько объектов на одном номере потребуют расширения модели.

`DELETE` с `{"id":"id кабинета"}` закрывает доступ и отзывает сессии. Кабинет не создаётся автоматически из любой заявки: это отдельное действие менеджера/серверной автоматизации после договора. Создание и публикация — реальные записи в CRM только после явного вызова соответствующего служебного endpoint.

## Публикация стройки

`PUT /api/internal/amocrm/cabinet` принимает `leadId` и `report`:

```json
{
  "leadId":123456,
  "report":{
    "name":"Александр",
    "project":"Сосновка",
    "area":96,
    "location":"Всеволожский район",
    "contract":"2026/042",
    "start":"2026-08-03",
    "finish":"2026-10-18",
    "progress":58,
    "manager":"Михаил · прораб",
    "stages":[
      {"title":"Фундамент","dates":"8–14 августа","status":"done","detail":"Установлен и проверен."},
      {"title":"Каркас и кровля","dates":"15 августа – 18 сентября","status":"active","detail":"Монтируем кровлю."},
      {"title":"Отделка","dates":"19 сентября – 18 октября","status":"planned","detail":"По согласованной комплектации."}
    ],
    "media":[
      {"id":"roof-1","kind":"photo","src":"https://media.example.com/roof.jpg","title":"Кровля","date":"2026-09-11","stage":"Кровля"},
      {"id":"video-1","kind":"video","src":"https://media.example.com/report.mp4","poster":"https://media.example.com/poster.jpg","title":"Видео с участка","date":"2026-09-11","stage":"Каркас"}
    ]
  }
}
```

Endpoint проверяет данные и сохраняет обычное примечание сделки с первой строкой `[Кабинет: стройка]`, а со следующей строки — JSON отчёта. Можно добавлять такое примечание своей автоматизацией непосредственно через API amoCRM. Последняя созданная публикация целиком заменяет предыдущую. Служебные статусы воронки сами по себе не становятся процентом готовности дома: этапы публикуются явно. Лимит отчёта — 16 000 символов, до 20 этапов и до 100 медиа (в пределах размера отчёта). `messages` из отчёта игнорируются.

Файлы не загружаются этим endpoint: нужны доступные браузеру HTTPS-ссылки на утверждённом хосте, для видео — MP4/WebM с поддержкой Range. Для конфиденциальных фото используйте защищённое хранилище и механизм обновления подписанных ссылок со стороны публикующей интеграции. Просроченная ссылка в примечании сама не обновляется. Вложения amoCRM с обязательной авторизацией напрямую в браузер не передаются. S3-подписание и загрузка файлов — отдельная следующая интеграция.

## Переписка

Сообщение клиента записывается в связанную сделку как common-примечание:

```text
[Кабинет: клиент]
{"text":"Когда установят окна?"}
```

Менеджер отвечает обычным текстовым примечанием с точным префиксом и переносом строки:

```text
[Кабинет: сообщение]
Окна привезут во вторник. После монтажа добавим фотографии.
```

Клиент видит только эти публикации. Остальные примечания, задачи, стоимость подрядчиков и внутренние поля сделки скрыты. Сообщение ограничено 2000 символами. Видны последние 200 опубликованных сообщений. Кабинет перечитывает данные раз в минуту, пока вкладка активна; доступна ручная кнопка обновления. Отправка показывается успешной только после подтверждения amoCRM. При неопределённом сетевом сбое сначала обновить переписку, чтобы не продублировать сообщение.

## Хранение и дальнейшее развитие

Непрозрачная сессия на 8 часов хранится в HttpOnly/SameSite=Strict cookie; на HTTPS — Secure. На диске — хеш токена, а не сам токен. Есть проверка Origin и ограничения попыток входа/сообщений. Клиент не передаёт ID сделки при получении данных или отправке сообщения; привязка берётся из аккаунта на сервере. Связь контакта и сделки повторно проверяется перед доступом к CRM.

Файловый адаптер `.cabinet/store.json` рассчитан на **один постоянно работающий Node-процесс** с постоянным диском. Он не подходит для serverless, нескольких реплик или общей папки нескольких Node-процессов. Для масштабирования перенести `transaction` в PostgreSQL/Redis. Каталог исключён из git; ограничить права доступа и резервировать вместе с аккаунтами. На Windows права задаются ACL каталога хостинга.

SMS пока не реализованы: будущий endpoint проверки одноразового кода должен выпускать ту же серверную сессию вместо проверки пароля. Для запуска потребуются провайдер, лимиты отправки, срок действия/одноразовость кода. Автоматическое создание аккаунтов из событий сделки потребует подключения серверной автоматизации к служебному API; вебхук не включён без настройки amoCRM.

Проверки: `npm run test:cabinet`; после запуска локального сайта — `npm run test:cabinet:http`. Второй набор предназначен только для `CABINET_MODE=demo`, создаёт и закрывает тестовые сессии. Реальный аккаунт amoCRM без настроенных ключей не проверялся.
