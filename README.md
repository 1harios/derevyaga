# Деревяга — сайт и личный кабинет

Продающий сайт строительной компании: каркасные дома под ключ, Санкт-Петербург
и Ленинградская область. Next.js на App Router, TypeScript, Tailwind, PostgreSQL.

Статус: **итерация 2 из 5** — все внутренние страницы: каталог с фильтрами,
карточки проектов, комплектации со сравнительной таблицей, калькулятор, цены,
технология, объекты, отзывы, о компании, гарантия, ипотека, FAQ, блог,
контакты, вакансии, SEO-страницы городов, sitemap и robots. Что дальше —
в конце файла.

## Запуск за пять минут

Нужен Node.js 20 или новее.

```bash
npm install
cp .env.example .env     # заполнять пока ничего не обязательно
npm run dev              # откроется http://localhost:3000
```

Боевая сборка:

```bash
npm run build
npm run start            # порт 3000
```

Статическая копия для показа вёрстки без сервера:

```bash
./scripts/build-preview.sh   # результат в ./out
node scripts/shots.mjs       # скриншоты главной на пяти разрешениях, в ./shots
node scripts/shots-all.mjs   # скриншоты ВСЕХ страниц: десктоп + мобильный
```

Шрифты лежат в проекте, а не подключаются с CDN. Если понадобится добавить
начертание, правьте список в `scripts/fonts.py` и запустите его: он скачает
файлы в `public/fonts` и перепишет блок `@font-face` в `globals.css`.

```bash
python3 scripts/fonts.py
```

Предметные снимки для блока технологии лежат на белом фоне. Привести
студийный фон нового снимка к чистому белому:

```bash
python3 scripts/whiten-bg.py public/photos/detal-uzel.webp
```

## Страницы второй итерации

Все страницы начинаются с той же светлой панели, что и главная (компонент
`PageHero`): внутри шапка, хлебные крошки, заголовок и подводка — сайт везде
открывается одинаково, а при прокрутке появляется знакомая плавающая пилюля.

- **/projects** — каталог с фильтрами по этажности, площади и спальням,
  сортировкой и честной заглушкой «ничего не нашлось». Фильтры — чипы,
  состояние видно с одного взгляда.
- **/projects/[slug]** — страница проекта: панель с фото, характеристики,
  планировочные решения, комплектации, этапы под срок проекта, похожие
  проекты и форма с пометкой, с какого проекта пришла заявка.
- **/complectations** — три карточки + сравнительная таблица по каждой строке
  сметы (данные в `src/content/complectations.ts`, согласованы со списками
  includes) и честные блоки «что не входит никуда» и «как переходят между
  комплектациями».
- **/calculator** — квиз-калькулятор на общем движке, без своего заголовка
  (его даёт PageHero), плюс три карточки о том, как устроен расчёт.
- **/prices** — ставки, коэффициенты и надбавки читаются из
  `pricing.config.ts` и показываются человеческим языком; три примера смет
  считаются движком прямо при сборке; график платежей — полосой долей.
- **/technology** — разрез стены (SVG-схема), шесть цифр стандарта,
  предметные образцы и блок «качество, которое можно проверить».
- **/objects** — сетка сданных объектов с план-фактом и честная приписка,
  почему объектов на странице пока три.
- **/reviews, /about, /guarantee, /mortgage, /faq, /contacts, /vacancies** —
  по аналогичной схеме; в FAQ вопросы сгруппированы по темам с якорями.
- **/blog** — три опорные статьи в `src/content/blog.ts`: структура блоков
  (абзац, подзаголовок, список, врезка) вместо markdown, чтобы вёрстка
  оставалась под контролем дизайн-системы.
- **/karkasnye-doma/[city]** — SEO-страницы шести городов: логистика
  считается из файла цен, объекты подтягиваются по району, перелинковка
  между городами и колонка «Строим в области» в футере.
- **/lk** и **/legal/*** — честные статус-страницы: витрина кабинета без
  фальшивой формы входа и состав будущих юридических документов без «рыбы».
  Обе закрыты от индексации.
- **/sitemap.xml, /robots.txt, 404** — карта сайта собирается из тех же
  данных, что и страницы.

## Как править цены

Все ставки и коэффициенты — в `src/lib/pricing/pricing.config.ts`. Файл читает
расчётный движок, который пойдёт на страницу калькулятора во второй итерации.
Цены за м² продублированы в витрине комплектаций `src/content/complectations.ts`.

## Как править тексты

Тексты вынесены из разметки в `src/content/*`. Менять их можно без знания React:
это обычные списки на TypeScript, в каждом файле видно, куда попадает значение.

## Дизайн-система

Макет сделан по утверждённому референсу: светлый холст, крупные скруглённые
панели, мягкие тени, монохром и заголовки обычным регистром. Токены заданы
в `src/app/globals.css` в блоке `@theme` и доступны как классы Tailwind
(`bg-surface`, `text-ink-soft`, `rounded-xl`, `shadow-card`).

Основные решения:

- Фоновая пара как в референсе: страница белая (`--color-canvas`), крупные
  панели светло-серые (`--color-panel`, #f2f1ef). Карточки белые с волосяной
  границей, чтобы читаться и на белом холсте, и на серой панели. Тёмные блоки —
  `--color-dark` (#1e2521): не чистый чёрный, а с зелёным подтоном, чтобы знак
  логотипа не выглядел на странице чужим.
- Блок технологии идёт без подложки. Белый 3D-рендер каркаса (как в референсе)
  стоит в потоке под текстом и свисает ниже секции отрицательным отступом,
  а панель каталога поднята слоем выше и накрывает его нижнюю часть. Каркас
  специально не абсолютный: в потоке он не может наехать на абзац ни на одной
  ширине экрана.
- Шапка наверху страницы без плашки: логотип, четыре ссылки и телефон.
  При прокрутке собирается в плавающую пилюлю — подложка проявляется, логотип
  уменьшается, справа выезжает кнопка. Анимируются только opacity и transform.
- Карточка каталога: фото на всю площадь, снизу градиент на фирменном мхе
  #4E6254, поверх — цена крупно, характеристики колонками и подпись со сроком.
- Фирменный мох `--color-brand` остался акцентом активных состояний, точек-маркеров
  и знака. Цветных заливок в интерфейсе нет — цвет отдан фотографиям.
- Скругления: карточки 20 px, панели 36 px, кнопки — пилюли. Тени мягкие,
  в двух ступенях: `--shadow-card` и `--shadow-float`.
- Типографика: заголовки Onest 500 обычным регистром, основной текст Inter
  300, 400 и 500. Капслок применяется только в мелкой технической подписи
  (класс `caption`). Оба семейства лежат локально в `public/fonts`
  и обновляются скриптом `scripts/fonts.py`.
- Роли текста сведены к четырём: заголовок, основной текст 16 px/1.65,
  вторичный через класс `muted`, подпись `caption` — мелкий капслок 12 px.
  На тёмных поверхностях `muted` сам переключается на белый с прозрачностью,
  поэтому у контейнера должен быть класс `on-dark`.
- Логотип используем как есть. Полная версия — не мельче 90 px по высоте,
  поэтому в шапке стоит только знак, а полный логотип живёт в подвале.
- Анимации 150–250 мс, только `opacity` и `transform`, с уважением
  к `prefers-reduced-motion`.
- Призывы к действию — единая пара из `src/content/company.ts`:
  `cta.primary` («Получить смету за 2 дня») ведёт к форме заявки,
  `cta.secondary` («Каталог проектов») — в каталог. Пилюля на фото первого
  экрана ведёт в калькулятор: это второй путь к смете, а не дубль кнопки.

Палитра и типографика из раздела 7 исходного брифа заменены на эту систему
по прямому указанию заказчика — референс с ними несовместим. Там же был запрет
на градиенты: заказчик его снял, градиенты используются на тёмных плашках
и в карточках каталога.

## Что убрано с главной

По решению заказчика с главной сняты четыре блока: калькулятор за 4 шага,
три комплектации, три шага до нового дома и способы оплаты. Во второй
итерации они заняли свои страницы: калькулятор — на «/calculator», комплектации —
на «/complectations» и в карточках проектов, этапы — на страницах проектов,
способы оплаты — на «/mortgage». Главная по-прежнему держит две точки захвата,
но теперь возражения закрываются внутренними страницами, на которые ведут
ссылки из шапки, футера и карточек.

Позже по референсам заказчика на главную добавлен компактный блок
«Почему выбирают нас» (WhyUsBlock, после первого экрана). Блок «Шесть шагов
к вашему дому» (BuildStepsBlock) с главной снят, а вместе с ним из кода
удалены неиспользуемые компоненты ObjectsSlider, ReviewsBlock, TeamBlock,
StagesBlock и ComplectationsBlock — все они остались в истории git
(до коммита «Пакет 0b»). Подробный график этапов с платежами живёт
на страницах проектов.

## Заявки

Форма отправляет `POST /api/lead`. Сейчас маршрут делает валидацию, нормализацию
телефона в `+7XXXXXXXXXX`, проверку honeypot, отсечку по времени заполнения и
ограничение частоты по IP, защиту от дублей 5 минут.

На третьей итерации туда добавится: запись в PostgreSQL, очередь доставки с
тремя попытками, адаптер CRM и отправка в Telegram. Порядок останется прежним:
сначала сохраняем заявку у себя и отвечаем клиенту, внешние сервисы дёргаем
в фоне — если CRM недоступна, заявка не теряется.

## Деплой на Beget

Next.js собирается в режиме `standalone`, то есть на хостинге не нужен
`node_modules`.

1. Соберите проект: `npm run build`.
2. Загрузите на сервер `.next/standalone`, `.next/static` (в `.next/standalone/.next/static`)
   и папку `public`.
3. Создайте `.env` рядом с `server.js` и заполните переменные.
4. Запустите приложение: `node server.js` под менеджером процессов Beget или pm2,
   порт задайте переменной `PORT`.
5. В панели Beget направьте домен на приложение и включите HTTPS.

База данных и файловое хранилище должны быть физически в России — этого требует
152-ФЗ. У Beget есть PostgreSQL, для файлов подойдёт любое S3-совместимое
хранилище российского провайдера.
